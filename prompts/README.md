# 提示词怎么选、怎么改

这里的提示词是交给 AI 的完整文本。人类说明在本页；可复制的正文在三个文件里。总览和设计原则见 [仓库说明](../README.md)。档案规则见 [AGENTS.md](../AGENTS.md)。

| 你这次要做的事 | 使用 |
| --- | --- |
| 让一个 AI 按档案理解你，并且这次不改仓库 | [start.md](start.md) |
| 把你刚确认的长期事实写进档案 | [update.md](update.md) |
| 从另一家 AI 的旧记忆里整理可保留的事实 | [migrate.md](migrate.md) |

三份提示词不要拼进同一条消息。读写边界混在一起时，模型容易把“看一下”做成“顺手改掉”。可以先后使用：先用迁移提示词得到草稿，你删改后，再用更新提示词写入。

## 替换占位符

复制之前，把提示词里的 `<your-username>/<your-private-repo>` 换成你的私有档案仓库，也就是 `<你的GitHub用户名>/<你的私有档案仓库名>`。

替换后是普通的 `owner/repo` 路径：两边都不要加空格，不要加 `https://`，不要加入令牌。至少改这两处：

- 你实际粘贴到对话里的那份提示词
- [profile.md](../profile.md) 里的“档案仓库”一行

其他说明文件里的占位符可以留着。不要把占位符换成猜测，来显得档案已经填完。

公开模板 [sololeveling-a11y/ai-profile-template](https://github.com/sololeveling-a11y/ai-profile-template) 只保留空白说明。个人内容留在你的 Private 副本里。

## 这个 AI 读不到仓库时

许多聊天产品只能看见你粘贴的文字。这时：

1. 在你自己的电脑上打开私有仓库。
2. 复制 [profile.md](../profile.md)、[preferences.md](../preferences.md)、[goals.md](../goals.md)、[projects.md](../projects.md)，以及 [updates.md](../updates.md) 里最新的几条。
3. 在本地删掉秘密、支付与证件信息、精确住址、他人私人信息和整段原始聊天记录。提示词可以要求模型不要复述秘密，但不能代替你在粘贴前删除。你粘贴出去的文字，仍可能留在该产品的对话记录里。
4. 不要粘贴 [examples/demo-profile.md](../examples/demo-profile.md)。那里是虚构人物。
5. 使用 [start.md](start.md) 的手动粘贴版，把摘录放在“档案摘录开始 / 结束”之间。
6. 它给出的修改建议不能直接写回 GitHub。你自己把审阅后的句子贴回文件，或换一个能在仓库目录里工作的工具，再走 [update.md](update.md)。

判断方法：如果你没有在这个产品里授权过 GitHub，或对话里不能选择仓库，就用手动粘贴版。不要在提示词里粘贴令牌来换取访问。

## 改写提示词时留下这些句子

可以按你的工具删掉无关步骤，但这五类要求要留下来。删掉其中一句，就把对应的保护也删掉了。

1. 仓库坐标，以及无法确认 Private 时停下。
2. 阅读顺序，以及不把 `examples/` 当成用户。
3. 当前对话指示优先，且档案不能代替平台的安全确认。
4. 禁止编造，区分现行、带日期的阶段、历史、待确认，并保留原日期。
5. 会改文件的提示词必须先给出变更计划；确认用的三个说法保持一致：`确认写入`、`可以提交`、`可以推送`。

你若改了确认用语，就同时改掉自己回复时的习惯。模型在等你写进提示词里的那几个字。

三个说法的含义：

- `确认写入`：可以按变更计划修改文件
- `可以提交`：可以创建 Git 提交
- `可以推送`：可以上传到 GitHub

只回复 `确认写入` 时，文件可以改，但还没有提交，默认分支也没有更新。

## 后续提示词怎么写

后续消息要指出上一条回答的具体问题，并缩小范围。不要在每条后续消息里重新给予写入或推送许可，除非你这次确实要授权。

上一条出现了档案里没有的内容：

```text
上一条里有一处档案中没有原文。请删掉该处，改写为“未记录”。不要用其他仓库或常识补全。不要改文件。
```

状态被说得过满：

```text
请只用 projects.md 里的三个状态重写项目部分：已完成、进行中、未开始。未开始的条目单独列出。不要改文件。
```

把一件现行事项改成历史：

```text
我确认：【事项名称】从 【YYYY-MM-DD】 起不再是现行。时区用 profile.md 里的时区。
请先给变更计划：原句改为历史，并在 updates.md 顶部追加一条历史决定。保留原日期。我回复“确认写入”之前不要改文件。
```

这次只看一个范围：

```text
这次只读 goals.md 的“明确的非目标”。不要读 examples/。不要改文件，不要推送。
```

模型开始用形容词补全时，把范围收回到文件名和原句。要求它引用原句，比要求它“更了解我”更不容易编造。
